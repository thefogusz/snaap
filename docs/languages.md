# Thai and English

All pages load `/language.js` before their UI scripts. The server renders static HTML in the selected language; browser modules translate only their static copy with `SnaapI18n.text`. User messages, saved names, identifiers and template interpolations remain unchanged. Existing workspace and setup names are preserved. New default workspaces and new alert-channel appearance settings follow the selected language.

The `snaap_language` cookie remembers the selected language for one year. First visits use the country supplied by an explicitly configured, edge-overwritten `COUNTRY_HEADER`, or a bounded server-side HTTPS lookup of the validated client IP with ipwho.is. Thailand selects Thai; other countries select English. Saved selections take priority over country. Unknown countries and provider failures fall back to the browser's highest-priority language, selecting Thai only for Thai. Country lookup stores no database records, retains at most 1,000 in-memory entries for 24 hours, coalesces concurrent reads and times out after one second. Pages and bootstrap responses use `no-store` to avoid sharing visitors' languages.

Railway already selects its overwritten `x-real-ip` header for client IPs. On other deployments configure `CLIENT_IP_HEADER` or `TRUST_PROXY_HOPS` appropriately. Set `COUNTRY_HEADER` only if the edge overwrites it and direct access to the origin is controlled. The free ipwho.is endpoint has a quota; use an edge country header at higher traffic. Provider documentation: https://ipwhois.io/documentation . Country follows the network IP, including VPN exits. The privacy page explains the IP-only lookup. Visitor messages, images and trading data are never sent for UI translation.

Language switching reloads the current route so existing modules and catalogs initialize consistently. The workbench preserves drafts, typed chat text and image references using its existing recovery storage, and blocks switching while a request is active or recovery cannot safely store unsaved work. A modal dialog must be closed before its background language button can be used.

`dist/translations/en.json` is a checked-in English catalog. It began with machine translation of static product copy; primary navigation, landing copy and trading terms have manual overrides. To add UI copy, wrap static literals with `globalThis.SnaapI18n?.text('ข้อความ') ?? 'ข้อความ'`, and translate each Thai phrase in the catalog. Translate static template segments before inserting user values. Do not translate a completed template containing user text or use translations as database keys, parsing rules or state identifiers. Date/number formatting uses `SnaapI18n.locale`. Draft status and sentiment styling use language-independent states.

The harness accepts an optional `language: 'th' | 'en'` per turn. It uses this or the UI cookie for ambiguous initial messages, follows the latest substantive user language, and retains the previous user language for ticker-only follow-ups. The language instruction is part of the current developer context, leaving the main instruction prefix stable for caching; specialist loads repeat it. Schemas, indicators, symbols and tool contracts remain language-independent. Explicit user language requests take precedence in the model guidance.

Validation: `npm test`, `npm run typecheck`, and `npm run test:harness`. The contract test uses a local provider fixture, including specialist loading and Thai/English transitions; it makes no paid model calls. Browser verification uses a fresh local database and test account, without production data.
