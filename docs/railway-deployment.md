# Snaap on Railway

## Deployment

- Public origin: `https://snaap.me`
- Repository: `https://github.com/thefogusz/snaap`, branch `main`
- Railway project: `ad7f10a3-d910-421c-99b7-5cc55264cd2e`
- Application service: `snaap`; database service: `Postgres`
- Start command: `npm start` (production entry point, no local test login).
- One application replica runs the API and signal monitor together.
- Keep Serverless disabled on both services so monitoring and the database remain available.
- Healthcheck path: `/api/v1/health`. This checks database connectivity; it does not prove end-to-end signal delivery or Google login.
- Application volume mount: `/data`; set `ASSET_STORAGE_PATH=/data/assets`.
- PostgreSQL has its own persistent volume. Production starts with a new database; local users, exchange keys and trading history are not automatically migrated.

## Application variables

```dotenv
APP_ORIGIN=https://snaap.me
BIND_HOST=0.0.0.0
PORT=8080
NODE_ENV=production
DATABASE_URL=${{Postgres.DATABASE_URL}}
ASSET_STORAGE_PATH=/data/assets
BILLING_LIVE_ENABLED=false
```

Set AI provider variables in Railway Variables, never in Git. `tsx` is a production dependency because the start command imports it.

Set a stable, random 32-byte hex `DATA_ENCRYPTION_KEY` before enabling private exchange connections or Discord. Keep a separate secure backup: replacing this key makes existing encrypted credentials unreadable. The local deployment backup is ignored by Git.

## Google login (required before users can sign in)

Follow [Google setup](google-auth-setup.md), using these production values:

- Authorized JavaScript origin, if requested: `https://snaap.me`
- Authorized redirect URI: `https://snaap.me/api/v1/auth/google/callback`
- Railway variables: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
- Public signup accepts every verified Google identity. `INVITED_EMAILS` is no longer used.
- With only `openid email` scopes, Google permits users outside the Test users list even in Testing; see [Google's basic identity scope exception](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview).

There is no public test account or login bypass. Without OAuth configuration, the login page can be deployed but users cannot enter the app.

## DNS at Spaceship

- Root `@` CNAME: use the target generated by Railway. Spaceship flattens root CNAME records.
- `_railway-verify` TXT: use the verification value generated by Railway.
- Allow DNS propagation and Railway certificate issuance to finish before checking HTTPS.

## Operations

- Inspect Railway resource usage after 24–48 hours; trial credit does not guarantee 30 days of runtime.
- AI calls are charged by the AI provider separately from Railway.
- Arrange independent PostgreSQL and asset backups before accepting important user data.
- To roll back application code, redeploy a previously successful deployment. Preserve database and volume contents.
- Trial restart retries and resource quotas are limited. A deployed monitor is not a guarantee of continuous uptime.
