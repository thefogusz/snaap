# Flow การทำงานของ Snaap

อ้างอิงโค้ดปัจจุบัน ณ 4 ตุลาคม 2026 แบ่งเป็นภาพรวมระบบและวงจรตรวจสัญญาณ

## 1. ภาพรวมระบบ

```mermaid
flowchart TD
    U[ผู้ใช้] --> A[เข้าสู่บัญชี]
    A --> P[ตรวจสิทธิ์ Free / Pro]
    P --> W[เลือกเวิร์กสเปซ]
    W --> C[แชท / แนบภาพ]
    W --> E[ตั้งค่าเซตอัปเอง]
    W --> H[ข้อมูลของฉัน]
    H --> HI[นำเข้าประวัติ / เชื่อม API บัญชี]
    HI --> HD[เก็บภาพและประวัติ พร้อมขอบเขตการใช้ข้อมูล]
    HD -. เปิดใช้ข้อมูลของฉันในแชท .-> C
    C --> AI[AI ช่วยถามข้อมูลและเสนอเซตอัป]
    AI --> D[ร่างเซตอัปเดียวกับหน้าตั้งค่า]
    E --> D
    D --> V[ตรวจความถูกต้อง]
    V --> G[กราฟอินดิเคเตอร์ / เล่นย้อนหลัง]
    G --> R[ผู้ใช้ตรวจและปรับเงื่อนไข]
    R --> D
    R --> S[บันทึกเซตอัปในเวิร์กสเปซ]
    S --> K[ส่งออกเป็นโค้ด]
    K --> I[ผู้รับวางโค้ด / ดูตัวอย่าง]
    I --> COPY[สร้างสำเนาในเวิร์กสเปซผู้รับ]
    COPY --> S
    S --> CONF[ผู้ใช้ยืนยันเปิดแจ้งเตือน]
    P -. จำกัดจำนวนเซตอัปที่เปิดใช้ .-> CONF
    CONF --> M[ระบบตรวจแท่งปิดจากกระดาน]
    M --> SIG[บันทึกสัญญาณและชื่อเซตอัป]
    SIG --> IN[กล่องสัญญาณในเว็บ]
    SIG --> OUT[คิวส่งแจ้งเตือน]
    OUT --> DEST[Telegram / LINE / Webhook ที่ยืนยันแล้ว]
    DEST --> DS[เก็บผลการส่ง / ส่งซ้ำเมื่อเหมาะสม]
    A --> B[บัญชีและแพ็กเกจ]
    B --> PAY[Stripe / ผลชำระเงินที่ตรวจสอบแล้ว]
    PAY --> P
    D -. เก็บร่างอัตโนมัติ .-> SAVE[กู้คืนเมื่อรีเฟรชหรือกลับมาใช้งาน]
```

- เวิร์กสเปซกำหนดชุดบทสนทนา เซตอัป และสัญญาณที่ผู้ใช้กำลังดู ส่วนภาพและประวัติมีขอบเขตการแชร์ข้อมูล
- AI เสนอและแก้ร่างได้ แต่ผู้ใช้เป็นผู้ยืนยันเปิดแจ้งเตือน ตั้งค่าเองได้แม้ AI ยังไม่พร้อม
- สำเนาจากโค้ดนำเข้ายังไม่เปิดแจ้งเตือน และไม่ผูกช่องทางแจ้งเตือนของเจ้าของเดิม
- การบันทึกร่างใช้ทั้งข้อมูลในเบราว์เซอร์และการบันทึกร่างที่ถูกต้องบนเซิร์ฟเวอร์ ข้อมูล API key ไม่ถูกเก็บในร่างของเบราว์เซอร์
- Free สร้างเวิร์กสเปซเพิ่มไม่ได้ สิทธิ์แพ็กเกจผูกกับบัญชี การลบเวิร์กสเปซที่สร้างเพิ่มย้ายบทสนทนา เซตอัป และขอบเขตข้อมูลไปพื้นที่หลัก

## 2. วงจรตรวจและสร้างสัญญาณ

```mermaid
flowchart TD
    START[เซตอัปที่เปิดใช้งาน] --> ACCESS{สิทธิ์ยังอนุญาตให้ตรวจ?}
    ACCESS -- ไม่ผ่าน --> BLOCK[แสดงสถานะหยุดตรวจตามสิทธิ์]
    ACCESS -- ผ่าน --> FETCH[รับข้อมูลตลาดผ่าน WebSocket / REST]
    FETCH --> VALID{ข้อมูลครบและมีแท่งปิดใหม่?}
    VALID -- ข้อมูลไม่พร้อม --> ERR[แสดงสถานะข้อมูลไม่พร้อม]
    VALID -- ยังไม่มีแท่งใหม่ --> WAIT[รอข้อมูลรอบถัดไป]
    WAIT --> FETCH
    VALID -- พร้อม --> CALC[คำนวณราคา วอลุ่ม และอินดิเคเตอร์]
    CALC --> SIDE[ประเมิน Spot / Long / Short ตามเซตอัป]
    SIDE --> CANCEL{เข้าเงื่อนไขยกเลิกขณะรอหรือมีสัญญาณค้าง?}
    CANCEL -- ใช่ --> CE[สัญญาณยกเลิก]
    CANCEL -- ไม่ใช่ --> ACTIVE{กำลังติดตามเงื่อนไขออก?}
    ACTIVE -- ใช่ --> EXIT{เงื่อนไขออกผ่าน?}
    EXIT -- ผ่าน --> XE[สัญญาณออก]
    EXIT -- ไม่ผ่าน --> WAIT
    ACTIVE -- ไม่ --> ENTRY{เงื่อนไขเข้าและขั้นตอนต่อเนื่องผ่าน?}
    ENTRY -- ยังไม่ผ่าน --> WAIT
    ENTRY -- หมดเวลารอขั้นตอน --> EX[สัญญาณหมดเวลารอ]
    ENTRY -- ผ่าน --> EN[สัญญาณเข้า]
    CE --> STORE[บันทึกเหตุการณ์พร้อมฝั่ง และป้องกันซ้ำ]
    XE --> STORE
    EX --> STORE
    EN --> STORE
    STORE --> SHOW[แสดงคู่เทรด ฝั่ง ราคา เวลา และชื่อเซตอัป]
    STORE --> SEND[ส่งไปช่องทางที่เลือกและยืนยันแล้ว]
    STORE --> STATE[เก็บสถานะการตรวจล่าสุดและช่วงพักตามกติกา]
    STATE --> WAIT
```

ถ้าเลือกทั้ง Long และ Short ระบบประเมินแยกกันและสร้างสัญญาณแยกฝั่ง เงื่อนไข Short ใช้แบบสลับจาก Long หรือกำหนดเองตามที่เลือกไว้ เงื่อนไขขั้นตอนต่อเนื่อง การออก ยกเลิก และช่วงพักเป็นตัวเลือกตามเซตอัป

## 3. ข้อมูลที่เก็บและความสัมพันธ์

```mermaid
flowchart LR
    ACCOUNT[บัญชี] --> PLAN[สิทธิ์แพ็กเกจและโควตา]
    ACCOUNT --> SPACE[เวิร์กสเปซ]
    SPACE --> CHAT[บทสนทนา / ข้อความ / ร่าง]
    SPACE --> SETUP[เซตอัปและประวัติการแก้ไข]
    SETUP --> SIGNAL[สัญญาณอ้างอิงเงื่อนไขตอนเกิดเหตุ]
    SIGNAL --> DELIVERY[ผลการส่งแต่ละช่องทาง]
    ACCOUNT --> CHANNEL[ช่องทางแจ้งเตือน]
    CHANNEL --> DELIVERY
    ACCOUNT --> DATA[ภาพ / ประวัติเทรด / บัญชีที่เชื่อม]
    DATA --> SCOPE[แชร์ทุกเวิร์กสเปซหรือเลือกเฉพาะพื้นที่]
    SCOPE --> SPACE
    SETUP --> SHARE[สำเนาเซตอัปสำหรับโค้ดแชร์]
```

ฐานข้อมูลหลักใช้ PostgreSQL และคิวงานใช้ pg-boss ภาพส่วนตัวเก็บผ่านระบบไฟล์ของแอป ส่วนข้อมูลกู้คืนร่างบางส่วนอยู่ในเบราว์เซอร์

ขอบเขตปัจจุบัน: ระบบสร้างสัญญาณแจ้งเตือน ไม่ส่งคำสั่งซื้อขายจริง การรัน Pine Script ใด ๆ และรับสัญญาณจาก TradingView เข้ามาโดยตรงยังไม่ใช่ความสามารถของ flow นี้ สูตร CUSTOM ที่นำเข้าได้เป็น JSON ตามรูปแบบที่ Snaap รองรับ บริการ AI ชำระเงิน และช่องทางภายนอกต้องตั้งค่าก่อนใช้จริง
