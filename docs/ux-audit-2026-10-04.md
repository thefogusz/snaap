# SNAAP UX audit — 4 October 2026

Scope: local application, actual rendered UI and interaction through the in-app browser. Goal: create, understand, review and save an alert rule without guessing what controls do. Existing charcoal/lime identity retained.

## Flow findings and changes

1. **Start a conversation / manual design — improved, AI service blocked.** The composer previously looked ready to send despite unavailable AI. A message now sits beside each composer and the send action is disabled; manual design remains usable. Saved conversation selection returns to chat. Screenshot: [start before](../qa/ux-01-before-home.png).
2. **Build a rule — improved.** Optional sequence/exit/cancel/cooldown settings now have a labeled disclosure. Grouped conditions show readable summaries before editing. Native disclosure markers make expansion apparent. Exit and cancellation have distinct headings and removable conditions. Form selectors retain focus and expanded group state after changes. Screenshot: [editor after](../qa/ux-09-editor-final.png).
3. **Validate and save — verified.** Required name, exchange, pairs and invalid numeric fields are checked before submission. Errors remain visible and focus the affected field; backend validation remains authoritative. Successful saves explain that a saved rule still needs activation and link to the rules list. Fixed false “unsaved” state caused by object-key order. Screenshot: [validation](../qa/ux-05-validation.png).
4. **Replay — verified with Binance public candle data.** The real action is called “ทดสอบย้อนหลัง”. The old navigation button called “ทดสอบ” merely scrolled to another button; navigation now names the sections it actually opens. Results gain a heading and receive focus/scroll when ready. Screenshot: [replay](../qa/ux-07-replay.png).
5. **Review activation and notifications — review verified; no rule activated.** “เพิ่มกฎ” starts a fresh draft instead of reopening the previous one. Inactive filter/status labels match. The activation dialog has a name and safe initial focus; its cancel action now describes cancellation instead of promising to edit. Existing unified notification tabs and official channel logos retained. Screenshots: [review](../qa/ux-06-review.png), [channels](../qa/ux-04-before-channels.png).
6. **Import and account — inspected, external integrations blocked.** Added a downloadable CSV header template; detailed format guidance is expandable. Unavailable primary actions use neutral styling. Screenshots: [import](../qa/ux-10-history.png), [account](../qa/ux-11-billing.png).

## Research basis

- [NN/g — Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/): expose core controls first, keep the route to advanced settings clear. Applied to optional settings and grouped conditions, without removing their summaries.
- [GOV.UK — Error summary](https://design-system.service.gov.uk/components/error-summary/): keep errors visible and help the user locate the input requiring correction. Applied as a persistent local feedback region with field focus and accessible invalid state; not a claim of implementing the entire GOV.UK component.

## Verification and limits

- Real-browser create/edit/save/reopen, grouped conditions, cancellation removal, validation focus, keyboard selection, activation review/cancel, and replay tested using an isolated QA rule. QA rule, conversation and two replay records removed afterward; no alert rule activated.
- Editor/replay checked at widths 320, 390, 768, 1024 and 1440. No page overflow detected in those states. Dark/light editor visually inspected. Grouped controls stayed within the editor at 390.
- JavaScript syntax checks, TypeScript check and all 19 existing unit tests passed. Browser error log empty. CSV template served successfully.
- AI conversation quality, paid checkout and external channel delivery cannot be verified without service configuration. No full screen-reader audit, real-user usability study, every nested rule combination, or complete WCAG conformance claim.
- Existing account-sync limitations remain documented in the product; this audit did not expand provider support or finish the backend release plan.
