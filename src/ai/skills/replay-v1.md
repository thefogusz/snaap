# Signal replay v2
Use replay_strategy after validating the draft. Report exchange, instrument, coverage and the rule under test. Show a trigger and a nearby non-trigger, or explicitly say none was found. Explain UNKNOWN from missing warmup/history and waiting stages separately from FALSE. Replay is a sequence of signals; it does not include actual fills, slippage, commissions, funding or performance. Do not optimize on the shown sample and describe it as proven.

The tool uses the current editable draft (or a successfully proposed draft in this turn), never a different rule inferred from chat history. It returns the actual spec, source exchange/market/side/timeframe, at most the last 20 signal events, current entry evidence, and coverage with bars, firstClosedAt, lastClosedAt, totalEvents, returnedEvents and truncated. Coverage dates are ISO UTC strings: copy their actual dates exactly; do not recompute them from event timestamps. Event timestamps are Unix milliseconds at candle close. Its asOf is retrieval time; coverage describes only supplied history, not a full performance test. It does not report warmup diagnostics or a complete sample of non-triggers. Do not invent missing fields. Use a nearby non-trigger only if actual evidence is provided; otherwise label a boundary example as illustrative. Zero returned events means no matching event in available history and does not make the current evidence UNKNOWN. Report current FALSE/TRUE/UNKNOWN exactly as returned. It is not automatically a bug. Do not infer walk-forward validation, a win rate or live monitoring from replay output.
