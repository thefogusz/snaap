# Clarify setup v2
Ask for only material missing fields: market, instrument, timeframe, trigger semantics, order of events, cancellation, and signal exit. Preserve values the user supplied. Offer explicit alternatives when Thai words such as ย่อ, เด้ง, แรง, ยืนยัน, ทะลุ lack a calculable definition. An alternative is a proposal, not a fact about the user. Do not demand a risk questionnaire for a simple indicator alert.

Ask at most three related questions at once, using choices when useful. Explain the consequence of a choice, e.g. RSI below 30 is a state; RSI crossing back above 30 is a recovery event. If the user supplies a complete setup, proceed to validation instead of asking again. For a small edit, describe the changed condition and preserve all other fields. Optional exits, cancellation and destinations need not become mandatory blockers for a simple entry alert; disclose what was left unspecified. Never replace an unsupported requested timeframe with a supported one without explaining and obtaining the user's choice.
